❯ The end result of this project is to have a working web crawler, which is     
  tested on web pages that use a limited subset of html (just href links). The  
  crawler must use multiple threads to achieve higher performance.              
                                                                                
  The crawler will have two groups of threads. The downloaders will be          
  responsible for fetching new pages from the Internet. The parsers will scan   
  the downloaded pages for new links. There are the circular interactions       
  between the two groups, meaning when a downloader fetches a new page, it      
  creates more work for a parser, and when a parser finds a new link, it        
  creates more work for a downloader.                                           
                                                                                
  I have split the workload into 3 parts: building the queues & visited         
  trackers, implementing thread pools & concurrency, and writing the main       
  crawler logic and callbacks.

     │                                                                         │
     │ my-crawler/crawler.c is empty. The assignment (requirements.md) is to   │

     │ for page content.                                                       │
     │ - Parsers scan content for <a href="...">, report each via edge_fn(),   │
     │ and push newly                                                          │

     │ queue is empty" is not a                                                │

     │ Design                                                                  │
     │                                                                         │
     │ One crawler_ctx, a local in crawl(), passed by pointer to every thread. │

     │ so the library stays reentrant.                                         │
     │                                                                         │
     │ 1. Links queue — bounded                                                │
     │                                                                         │
     │ Circular buffer of char *, capacity work_queue_size. Condvars           │
     │ not_empty, not_full.                                                    │
     │ Producers: parsers + the seed. Consumers: downloaders.                  │
     │                                                                         │
     │ 2. Page queue — unbounded                                               │
     │                                                                         │
     │ Linked list of {char *url; char *body;}. Condvar not_empty. Producers:  │
     │ downloaders.                                                            │
     │ Consumers: parsers.                                                     │
     │                                                                         │
     │ This is the load-bearing decision. With both queues bounded, parsers    │
     │ blocked on a full links                                                 │
     │ queue and downloaders blocked on a full page queue deadlock cyclically. │
     │ An unbounded page queue                                                 │
     │ means downloaders never block on a push, so they always drain the links │
     │ queue, so a parser blocked                                              │
     │ in link_push is always released. Proof sketch to put in a comment:      │
     │                                                                         │

     │ ▎ links queue is full;                                                  │

     │ ▎ link_pop, and                                                         │

     │ ▎ Contradiction.                                                        │
     │ ▎ Otherwise every parser is in page_pop and every downloader in         │
     │ ▎ link_pop with both queues                                             │
     │ ▎ empty and no item in hand ⟹ pending == 0 ⟹ legitimate termination.    │
     │                                                                         │
     │ The proof needs work_queue_size >= 1; at capacity 0, full and empty are │

     │ 3. Visited set — hash set, chaining                                     │
     │                                                                         │

     │                                                                         │

     │ parent before the pushes                                                │
     │ drain, or pushing before incrementing, breaks both the premature-zero   │

     │ invariants at once.                                                     │
     │                                                                         │

     │                                                                         │

     │                                                                         │

     │ unlock                                                                  │

     │ destroy mutexes/condvars                                                │

     │                                                                         │
     │ Step 4 above step 3 is a use-after-free, and destroying a mutex with a  │

     │ enters cond_wait. The flag must live inside each queue struct, be       │

     Multi-threaded Web Crawler (libcrawler.so)

     Context

     my-crawler/crawler.c is empty. The assignment (requirements.md) is to
     implement one exported
     function, crawl(), in a pthreads shared library that crawls a page graph
     using two cooperating
     thread pools:

     - Downloaders pop URLs off a bounded links queue and call fetch_fn() for
     page content.
     - Parsers scan content for <a href="...">, report each via edge_fn(), and
     push newly
     discovered URLs back onto the links queue.

     The pools feed each other, which is the actual difficulty: a cyclic
     producer/consumer
     relationship over a bounded buffer. A naive design deadlocks, and "the
     queue is empty" is not a
     valid stopping condition — a parser may be about to produce more links. The
     driver runs 4
     downloaders, 4 parsers, work_queue_size = 10 against a 1000-page corpus, so
     producers block
     constantly; the synchronization is genuinely exercised.

     Outcome: make libcrawler.so builds clean under -Wall -Werror, and
     LD_LIBRARY_PATH=. ./crawl <testdir> prints the full edge list and
     terminates.

     Constraints

     - Split across small single-purpose modules so crawler.c stays readable;
     crawl() is the only
     exported symbol, everything else static or internal. The Makefile globs *.c
     *.h, so any number
     of files in my-crawler/ get compiled into the one .so with no Makefile
     change.
     - C + POSIX pthreads, built -fpic -Wall -Werror -pthread -shared. Zero
     warnings tolerated.
     - api.h is not on the include path — #include 
     "../os-crawler-framework/api.h".
     - Clean pool exit is not required by the spec, but crawl() returning is.
     - A hash function may be copied from online only with a source-URL comment.

     Settled semantics

     - edge_fn(from, to) = "encountered a link on from to to" → fire once per <a
     href>
     occurrence, unconditionally, before and independent of the visited check.
     Visited-filtering
     gates queueing only, never edge reporting. (Gating edges on the visited
     check yields 999
     instead of 12896 on test3.)
     - Only the href attribute is a link. Also matching the >NAME</a> anchor
     text double-counts to 25792.
     - fetch_fn() returns a malloc'd buffer we must free(), or NULL for a broken
     link.
     - crawl() returns 0 / -1.

     Module map

     Mirrors the three-way split of the work. Each .c owns exactly one
     synchronized structure and
     exposes an interface that never leaks a held lock to its caller.

     Module: queue.{h,c}
     Owns: bounded link queue (ring of char*) + the pending counter + all_done;
     unbounded page queue
     Key interface: lq_init/push/pop/stop/destroy, lq_pending_inc/dec,
     lq_wait_done,
     pq_init/push/pop/stop/destroy
     ────────────────────────────────────────
     Module: visited.{h,c}
     Owns: hash set + hash function
     Key interface: visited_init, visited_insert → bool, visited_destroy
     ────────────────────────────────────────
     Module: pool.{h,c}
     Owns: thread-pool create/join
     Key interface: pool_start(&p, n, fn, arg), pool_join(&p)
     ────────────────────────────────────────
     Module: parse.{h,c}
     Owns: link extraction from a page body
     Key interface: parse_links(body, cb, arg) or a cursor-style next_link()
     ────────────────────────────────────────
     Module: crawler.{h,c}
     Owns: crawler_ctx, crawl(), downloader + parser loops, edge_fn
     serialization
     Key interface: crawl() (the only exported symbol)

     Two notes on the boundaries:

     - pending lives in queue.c with the link queue, not in its own module. It
     is deliberately
     guarded by the same mutex as the bounded ring — that is what makes "a
     blocked pusher has already
     counted its child" true by construction (see §4). Splitting the counter
     into its own file with its
     own mutex would re-open the premature-zero bug. The two belong to one
     synchronized unit, so they
     ship in one file.
     - parse.c is pure, no locks, no threads — trivially unit-testable in
     isolation, which is the main
     reason to break it out.

     Design

     One crawler_ctx, a local in crawl(), passed by pointer to every thread. No
     file-static state,
     so the library stays reentrant.

     1. Links queue — bounded

     Circular buffer of char *, capacity work_queue_size. Condvars not_empty,
     not_full.
     Producers: parsers + the seed. Consumers: downloaders.

     2. Page queue — unbounded

     Linked list of {char *url; char *body;}. Condvar not_empty. Producers:
     downloaders.
     Consumers: parsers.

     This is the load-bearing decision. With both queues bounded, parsers
     blocked on a full links
     queue and downloaders blocked on a full page queue deadlock cyclically. An
     unbounded page queue
     means downloaders never block on a push, so they always drain the links
     queue, so a parser blocked
     in link_push is always released. Proof sketch to put in a comment:

     ▎ Suppose all threads block forever. If any parser is in link_push, the 
     ▎ links queue is full;
     ▎ capacity ≥ 1, so full ⟹ non-empty, so no downloader can be waiting in 
     ▎ link_pop, and
     ▎ page_push never blocks — so some downloader must pop, freeing a slot. 
     ▎ Contradiction.
     ▎ Otherwise every parser is in page_pop and every downloader in link_pop 
     ▎ with both queues
     ▎ empty and no item in hand ⟹ pending == 0 ⟹ legitimate termination.

     The proof needs work_queue_size >= 1; at capacity 0, full and empty are
     both true and the first
     push deadlocks. The argument validation is load-bearing, not cosmetic —
     comment it as such.

     Not truly unbounded in practice: visited guarantees each URL is enqueued at
     most once, so the
     page queue holds at most |reachable pages|. test3's entire corpus is 6.0
     MB.

     3. Visited set — hash set, chaining

     Fixed 1024 buckets (1000 entries → chains of ~1; no resizing). djb2
     accumulated in
     unsigned long over unsigned char, with the source URL cited in a comment
     per spec.
     Accumulating in int is signed-overflow UB and can yield a negative bucket 
     index.
     Avoid fletcher32 — it wants uint16_t*, so it type-puns char* and over-reads
     odd-length strings.

     Two hard rules:
     - visited_insert() locks, tests-and-inserts, unlocks, and returns a bool.
     Check-then-add as
     separate calls is a race causing duplicate downloads.
     - It strdups its own key. If it stores the caller's pointer, that pointer
     is later freed by
     whichever parser handles that page, leaving ~1000 dangling keys that the
     next strcmp reads.

     4. Termination detection — outstanding-work counter

     long pending, folded into the links-queue mutex along with condvar all_done
     (3 mutexes
     total: links, pages, edge). pending counts items existing anywhere — queued
     links + queued
     pages + items in a worker's hands. Every transition conserves it:

     ┌────────────────────────────────────┬────────────────────────────────────┐
     │             Transition             │              pending               │
     ├────────────────────────────────────┼────────────────────────────────────┤
     │ seed, before pthread_create        │ 0 → 1                              │
     ├────────────────────────────────────┼────────────────────────────────────┤
     │ link_pop                           │ unchanged (queue → hand)           │
     ├────────────────────────────────────┼────────────────────────────────────┤
     │ fetch returns NULL                 │ −1                                 │
     ├────────────────────────────────────┼────────────────────────────────────┤
     │ page_push                          │ unchanged, deliberately (hand →    │
     │                                    │ page queue)                        │
     ├────────────────────────────────────┼────────────────────────────────────┤
     │ page_pop                           │ unchanged                          │
     ├────────────────────────────────────┼────────────────────────────────────┤
     │ parser finds a new target          │ +1                                 │
     ├────────────────────────────────────┼────────────────────────────────────┤
     │ parser finds an already-visited    │ unchanged (edge still emitted)     │
     │ target                             │                                    │
     ├────────────────────────────────────┼────────────────────────────────────┤
     │ parser finishes a page (incl.      │ −1                                 │
     │ zero-outlink)                      │                                    │
     └────────────────────────────────────┴────────────────────────────────────┘

     So pending == 0 ⟺ both queues empty and no hand holds anything — and it is
     an absorbing
     state, because every +1 is performed by a thread that is itself holding a
     counted item. Main
     can therefore shut down on observing 0 with no re-check.

     Folding the counter into the links mutex makes pending_inc + link_push a
     single critical
     section, so the key invariant holds by construction rather than by
     discipline:

     lock(Lq);
       pending++;
       while (full && !stop) wait(not_full, Lq);
       if (stop) { pending--; unlock(Lq); free(s); return; }
       ring[tail] = s; ...; signal(not_empty);
     unlock(Lq);

     cond_wait releases the mutex, so downloaders still drain. A parser blocked
     here has already
     counted its child and not yet discounted its parent, so pending >= 2 and
     main cannot see 0.

     5. Worker loops

     Downloader: url = link_pop() → body = fetch_fn(url) → if NULL, free(url) +
     pending_dec(); else page_push(url, body) and touch neither pointer again (a
     defensive
     free after the push is a double free — null the locals).

     Parser: page = page_pop() → scan with strstr → per target:
     edge_fn(page.url, target) under
     the edge mutex, then if (visited_insert(target)) { pending_inc(); 
     link_push(strdup(target)); } →
     after the loop free(body); free(url); pending_dec().

     That final pending_dec() must be last — comment it. Decrementing the parent
     before the pushes
     drain, or pushing before incrementing, breaks both the premature-zero and
     the no-blocked-pusher
     invariants at once.

     6. crawl()

     Validate (NULL start_url/fetch_fn, non-positive workers or queue size →
     -1). Init, seed
     visited + links queue with pending = 1 before spawning, spawn both pools,
     then:

     lock(Lq);
     while (pending != 0) pthread_cond_wait(&all_done, &Lq);   /* while, not if
     */
     unlock(Lq);

     Teardown order is the whole ballgame:

     1. observe pending == 0
     2. per queue: lock it, set its stop flag, broadcast its condvars, unlock
     3. pthread_join all threads
     4. only now free the ring, every visited key/node/bucket array, and destroy
     mutexes/condvars
     5. return 0

     Step 4 above step 3 is a use-after-free, and destroying a mutex with a
     waiter is undefined.

     Bugs the design review caught — fix these by construction

     1. Stop flag set outside the queue mutex → lost wakeup → pthread_join hangs
     forever. A worker
     can evaluate its predicate, then main sets the flag and broadcasts before
     the worker actually
     enters cond_wait. The flag must live inside each queue struct, be written
     and read under
     that queue's mutex, and use broadcast (4 downloaders may be parked).
     volatile does not fix
     this — the race is on wait/flag ordering, not visibility. Don't name it
     shutdown; that collides
     with POSIX shutdown(2). Use stop.
     2. Main must use a while predicate loop. On a small graph pending can reach
     0 before main
     finishes pthread_create; a broadcast with no waiter is a no-op and crawl()
     hangs forever.
     3. visited_insert must own its key via its own strdup (see §3) — otherwise
     use-after-free.
     4. Allocation failure must pending_dec(). If strdup/malloc returns NULL
     after the
     increment, the item evaporates but the count doesn't, and crawl() never
     returns. Three sites;
     check each and drop the item. A hang is far worse than a dropped edge.
     5. Never hold one lock while acquiring another. No two locks are ever held
     simultaneously, which
     makes a lock-order cycle impossible by construction — enforce it as a rule:
     no mutex is held
     across fetch_fn, edge_fn, link_push, page_push, pending_*, or any malloc.
     The
     tempting refactor that holds the visited lock across the push serializes
     every parser behind one
     blocked parser; fetching while holding the links mutex deadlocks outright.

     Also: strchr for the closing quote can return NULL on truncated input —
     check before
     dereferencing. Advance the scan pointer past the close quote (past p alone
     rescans; by 0 loops
     forever). Extract with malloc(len+1) + memcpy + explicit NUL, not strncpy

     -Wstringop-truncation, which is in -Wall) and not by writing '\0' into the

     broadcast, join what was created, tear down, return -1.
